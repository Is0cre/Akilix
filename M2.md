# Akilix M2 — Reproducible Tool Execution

The initial M2 foundation is implemented independently of the CLI:

- immutable OCI digest resolution through Podman inspection
- explicit argument-vector runner
- digest-pinned image references
- private network, PID, IPC, and UTS namespaces
- `keep-id` rootless mapping
- read-only root filesystem by default
- `no-new-privileges` and dropped capabilities
- original-evidence mounts required to be read-only
- deterministic environment and working-directory handling
- local `akilix container inspect IMAGE` digest inspection
- digest-pinned `akilix container run WORKBOOK IMAGE [--target TARGET] [--override] -- COMMAND [ARGS...]`
- explicit `--workdir DIR` and repeated `--env KEY=VALUE` options
- canonical `.akilix/containers/<invocation-id>.json` policy manifests
- policy manifests record effective namespaces, pull policy, capability drop,
  root filesystem mode, mount classifications, and generated files
- offline `akilix container doctor` validation of rootless Podman and its user
  namespace
- regression coverage ensuring mount options precede the image reference
- explicit, symlink-resistant `--mount-originals` workbook mount at the fixed
  `/workbook/evidence/original` path; original evidence is never mounted by
  default and is always read-only
- invocation-specific `--mount-output` storage at `/workbook/output`, with
  generated files attributed beneath `artifacts/derived/<invocation-id>/`

Remaining M2 work is primarily runtime integration testing on a host where
rootless Podman user namespaces and digest-pinned local images are available.

## Example

```sh
akilix container inspect registry.example/tool:1
akilix container run client-2026 registry.example/tool:1 \
  --target 10.20.30.40 --json -- tool --version
```

The first command must resolve a local image to a digest. Container execution
does not silently pull images or bypass workbook scope.
