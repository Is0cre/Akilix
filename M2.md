# PenSUSE M2 — Reproducible Tool Execution

The initial M2 foundation is implemented independently of the CLI:

- immutable OCI digest resolution through Podman inspection
- explicit argument-vector runner
- digest-pinned image references
- private network, PID, IPC, and UTS namespaces
- `keep-id` rootless mapping
- read-only root filesystem by default
- `no-new-privileges` and dropped capabilities
- original-evidence mounts required to be read-only
- deterministic environment and working-directory handling
- local `pensuse container inspect IMAGE` digest inspection
- digest-pinned `pensuse container run WORKBOOK IMAGE [--target TARGET] [--override] -- COMMAND [ARGS...]`

Remaining M2 work includes wiring these specs into workbook invocation
provenance, stdout/stderr artifact capture for containers, generated-file
tracking, and runtime integration tests on a host where rootless Podman user
namespaces are available.

## Example

```sh
pensuse container inspect registry.example/tool:1
pensuse container run client-2026 registry.example/tool:1 \
  --target 10.20.30.40 --json -- tool --version
```

The first command must resolve a local image to a digest. Container execution
does not silently pull images or bypass workbook scope.
