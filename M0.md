# PenSUSE M0 — Architecture and Platform Foundation

## Objective

Produce the smallest bootable PenSUSE development system that proves the project's platform assumptions.

M0 does NOT build a penetration-testing distribution.

M0 establishes the foundation upon which later security functionality can safely be built.

---

# Deliverables

M0 must provide:

1. repository structure
2. architecture documentation
3. Go module
4. minimal `pensuse` binary
5. version command
6. basic configuration mechanism
7. RPM packaging skeleton
8. KIWI NG image definition
9. openSUSE Leap 16.x bootable development image
10. Btrfs/Snapper verification
11. rootless Podman verification
12. automated test entry points
13. build documentation
14. security baseline inspection

# CLI requirement

M0 must implement:

    pensuse version

Expected conceptual output:

    PenSUSE 0.0.1-m0
    Base: openSUSE Leap 16
    Architecture: x86_64

Machine-readable support should be considered:

    pensuse version --json

Example conceptual structure:

    {
      "name": "PenSUSE",
      "version": "0.0.1-m0",
      "base": "openSUSE Leap 16",
      "architecture": "x86_64"
    }

Exact version injection mechanism may be determined during implementation.

# Configuration

Establish configuration lookup rules.

Recommended order:

1. command-line options
2. environment where appropriate
3. user configuration
4. machine configuration
5. compiled defaults

Do not introduce a large configuration framework.

Use XDG paths where appropriate for user configuration/state.

System-wide PenSUSE state should use conventional Linux filesystem locations.

---

# Image

Produce a declarative KIWI NG definition capable of producing a development VM image.

Initial VM support is more important than producing a polished ISO.

The image should contain only what M0 requires.

Expected baseline components include:

- openSUSE Leap 16.x base
- Btrfs
- Snapper
- SELinux
- systemd
- Podman
- zsh
- Git
- PenSUSE package
- basic administration/debugging utilities

Do not install broad offensive-security package collections.

---

# Btrfs test

Verify that the development image:

- uses the intended Btrfs system layout
- has functioning Snapper configuration
- can create a pre-change snapshot
- can create a post-change snapshot
- can restore/rollback system state in a controlled test

Workbook storage is not required in M0 but filesystem design must avoid coupling future workbook data to system rollback.

---

# Podman test

Verify:

    podman info

works for an ordinary non-root PenSUSE user.

Run a minimal rootless test container.

No security tool container profile is required yet.

---

# Network baseline

Inspect listening sockets in the booted M0 image.

PenSUSE itself must not introduce unexpected network listeners.

Create an automated or semi-automated check using tools available in the base system.

Expected state:

- no PenSUSE telemetry service
- no PenSUSE remote-control daemon
- no automatically started pentest listener
- no automatically started attack infrastructure

Existing openSUSE services should be deliberately reviewed rather than blindly accepted.

---

# Packaging

Create an RPM packaging skeleton for the PenSUSE CLI.

The package must install files into conventional RPM/openSUSE locations.

Do not install development files into `/opt/pensuse` simply to avoid learning packaging conventions.

---

# Build commands

Provide documented local commands for:

- building Go binary
- running tests
- building RPM
- building development image

Prefer Makefile or another thin task layer if useful.

Do not make the task runner become a second build system.

---

# Tests

M0 must contain at minimum:

## Unit

Tests for version/configuration functionality where applicable.

## CLI

Verify:

    pensuse version

and machine-readable equivalent.

## Packaging

Verify expected binary installation path and package metadata.

## VM

Boot produced image.

Verify:

- system reaches expected target
- PenSUSE CLI exists
- Btrfs available
- Snapper works
- Podman rootless works
- SELinux state is known
- no PenSUSE-specific listener exists

---

# M0 exclusions

Do NOT implement during M0:

- workbook implementation
- evidence importing
- forensic acquisition
- Nmap wrappers
- Metasploit
- Burp Suite integration
- SQL injection tools
- password cracking environments
- AD exploitation
- wireless attacks
- malware detonation
- local LLM
- remote LLM
- GUI
- TUI
- privileged daemon
- security-tool marketplace
- hundreds of packages

If a feature does not help prove the platform foundation, defer it.

# M0 acceptance criteria

M0 passes when all of the following are true:

    [ ] Repository architecture documented
    [ ] Project invariants documented
    [ ] Go project builds cleanly
    [ ] Unit tests pass
    [ ] `pensuse version` works
    [ ] `pensuse version --json` works
    [ ] RPM can be built
    [ ] RPM installs successfully on Leap 16
    [ ] KIWI development VM image builds
    [ ] Development image boots
    [ ] Btrfs layout inspected and documented
    [ ] Snapper snapshot creation works
    [ ] Rollback procedure tested
    [ ] Podman rootless execution works
    [ ] SELinux baseline documented
    [ ] PenSUSE introduces no unexpected listeners
    [ ] PenSUSE introduces no telemetry
    [ ] Build procedure is documented
    [ ] Important failure paths have tests

---

# Required implementation behavior

Codex or any other implementation agent must:

1. inspect the running Leap 16 system rather than assume package/service behavior
2. prefer upstream openSUSE mechanisms
3. document discovered differences between the architecture assumptions and the real system
4. avoid scope expansion
5. keep dependencies minimal
6. add tests with implementation
7. report exactly what was changed
8. report tests that were actually executed
9. report failures honestly

---

# M0 completion report

The implementation is being established incrementally. The initial repository
foundation now includes the Go module, version/configuration packages, CLI
tests, RPM skeleton, KIWI definition, network-baseline script, and build guide.
Image, Snapper, Podman, and SELinux verification remain environment-dependent
until the required openSUSE build and VM tooling is available.

Current host validation has since confirmed Go tests, `go vet`, CLI build, RPM
build, and rootless Podman capability. The bootable Leap 16 ISO now supports
both BIOS and UEFI and contains the CLI/completions. Runtime Btrfs, Snapper,
Podman, and SELinux observations are collected by `make vm-check` in the
booted environment and remain pending on the hardware test host.
