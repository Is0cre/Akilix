# PenSUSE M1 — Workbook Foundation

M1 begins with the filesystem-canonical workbook model. The current slice
implements workbook creation, listing, passive opening, and status inspection.

## Implemented

- UUIDv7-style immutable workbook IDs
- Human-readable names that remain separate from identity
- Versioned `workbook.yaml` metadata
- Explicit workbook directory layout
- Initial `scope.yaml` and README files
- Atomic metadata writes and duplicate-name rejection
- `PENSUSE_WORKBOOK_ROOT` override for tests and local development
- `pensuse workbook create|list|open|status`
- `pensuse workbook validate` performs a read-only layout and evidence integrity audit
- Explicit `pensuse workbook close` lifecycle transition
- Explicit `pensuse workbook reopen` lifecycle transition
- Safe workbook rename preserving immutable identity
- SHA-256 evidence import with immutable original storage
- Evidence sidecar manifests and verification
- `pensuse evidence import|list|verify`
- `pensuse evidence verify WORKBOOK --all [--json]`
- Include/exclude scope entries and structured local checks
- Explainable scope decisions with matched-rule provenance and versioned JSON schema
- `pensuse scope add|exclude|list|check`
- Explicit-vector native managed execution with stdout/stderr capture
- Invocation JSONL provenance records and failure status
- Safe environment allowlist and working-directory provenance
- `pensuse run WORKBOOK -- COMMAND [ARGS...]`
- Optional target scope decisions and explicit override provenance on runs

## Safety properties

Workbook operations are local filesystem operations only. Opening or inspecting
a workbook does not contact the network, invoke tools, or start listeners.
Container execution, immutable OCI identity, and richer scope enforcement are
later increments; this native executor intentionally uses no shell string and
does not claim containment.

## Remaining M1 work

- richer typed scope schema and override records
- managed execution environment manifests
- additional failure-path and filesystem fixture tests
- initial OCI invocation adapter

The first M2-compatible component, immutable OCI digest resolution, is now
available under `internal/container` and is tested independently of Podman.
